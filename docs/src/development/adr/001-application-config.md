# ADR-001 : 設定の参照方法に関する意思決定

- 作成日 ： 2026/11/13
- 関連ADR : 無し

## 背景

Lixy を開発していく上で設定の参照方法を早い段階で決定する必要が生まれた。
設定値の参照方法を検討するうえで以下に示す要求が存在した。

- 設定値に依存する箇所の把握を容易にしたい。
- 設定値に依存する箇所のテストを容易に行いたい。

## 決定

- アプリケーションの起動時に1度だけ設定を読み込み、アプリケーション内で書き換えない
- 設定は構造体に割り当てられた後、必要とする箇所にDIしていく

## 理由

- 本プロジェクトにおいて設定値を動的に変更したいユースケースは存在しないため、最初に一度だけ読み込んだ上で設定の構造体を引き回したほうが良いと判断した。
- 設定をDIする事により設定値に依存する箇所のテストが容易になる他、コードに現れない依存を排除することにつながると判断した。

## 検討した選択肢

### viper等を用いた直接取得

`viper.GetString()`等のAPIを用いて、設定値を必要とする箇所が直接取得する方式はDIが不要であったりコードが簡潔になるなどのメリットが有る。
一方で、設定値に依存するテストが難しくなることや、設定のキーがただの文字列として書かれることにより設定のキーを変更した際に修正漏れが生じるリスクがある。
これらのメリット・デメリットを考慮し、今回は採用を見送ることにした。

## 影響

- 設定値を必要とする箇所ではファクトリー関数やコンストラクタ経由で設定値を注入する必要がある。
- 設定値への依存がファクトリー関数やコンストラクタの引数として現れるため、設定値に依存している箇所の追跡が容易になる。
- 設定値を変更した場合、アプリケーション自体の再起動が必要となる。
